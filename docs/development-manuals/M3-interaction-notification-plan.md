# M3 互动与通知开发规划

## 阶段定位

M3 的目标是把 ThreadMind 从“能发帖和回复”推进到“有持续互动反馈的论坛”。这一阶段重点不是 AI，而是论坛用户每天会反复使用的互动和通知能力。

M3 完成后，用户应能清楚知道自己点赞了什么、收藏了什么、有没有新回复或系统消息；首页热门排序和通知入口也应基于真实数据。

## 核心目标

- 点赞和收藏具备真实当前用户状态，不再只做计数变化。
- 通知中心成为正式页面，支持列表、未读状态和标记已读。
- 首页热门排序、待回复排序和统计口径与后端一致。
- 增加个人收藏入口，用户可以找回收藏主题。
- 管理和普通用户流程继续保持权限边界。
- 补充后端服务测试、前端 API 状态处理和联调验收手册。

## 功能范围

### 1. 点赞和收藏状态

后端建议新增：

- `GET /api/topics/{id}/interaction-status`
- `GET /api/replies/{id}/interaction-status`

返回：

```json
{
  "targetType": "TOPIC",
  "targetId": 101,
  "liked": true,
  "favorited": true,
  "likeCount": 8,
  "favoriteCount": 3
}
```

前端要做：

- 帖子详情页根据真实状态显示已点赞、已收藏。
- 重复点击支持取消点赞、取消收藏。
- 操作失败时不乐观更新，展示错误。

### 2. 通知中心

后端已有：

- `GET /api/notifications`
- `POST /api/notifications/{id}/read`

M3 需要补：

- 通知未读数接口，或在列表接口中由前端统计未读。
- 通知 payload 的稳定字段约定。
- 回复通知、点赞通知、系统通知的展示规则。

前端要做：

- 新增通知页面。
- 顶部通知按钮显示未读状态。
- 通知可标记已读。
- 空状态、加载失败、无权限状态都有明确展示。

### 3. 个人收藏

后端建议新增：

- `GET /api/users/me/favorites`

前端要做：

- 增加个人收藏列表入口。
- 收藏列表复用 TopicList。
- 收藏为空时显示可操作空状态。

### 4. 热门和待回复排序

后端需要统一排序语义：

- `sort=latest`：按创建时间。
- `sort=hot`：按点赞、回复、收藏、浏览综合分。
- `sort=unanswered`：回复数为 0 或低回复主题。

当前前端使用 `hot`，后端已有 `hottest` 分支，M3 需要统一为 `hot`。

### 5. 通知写入规则

M3 需要明确：

- 用户回复自己的帖子时是否通知自己。建议 MVP 不通知自己。
- 用户点赞自己的帖子时是否通知自己。建议不通知自己。
- 重复点赞不重复写通知。
- 取消点赞不删除历史通知。
- 治理处理结果是否通知举报人。建议通知。

## 推荐开发顺序

1. 后端补 interaction status 查询和取消接口返回一致状态。
2. 后端修正 `sort=hot` 语义并补测试。
3. 后端补通知未读数或稳定列表统计。
4. 前端帖子详情页接真实 liked/favorited 状态。
5. 前端新增通知中心页面。
6. 前端新增个人收藏入口。
7. 更新 API 契约、模块文档和 M3 开发手册。
8. 更新 `verify-local-flow.ps1`，加入取消点赞、取消收藏、标记通知已读验收。

## 数据和接口注意事项

- 不新增 Redis，继续使用 MySQL 完成 MVP。
- `reactions` 和 `favorites` 已有唯一索引，M3 应利用唯一约束保证幂等。
- 通知 payload 必须继续使用 JSON，但高频查询字段不要藏在 payload 里。
- 任何用户态状态查询都必须走 JWT 当前用户。
- 游客仍可浏览公开帖子，但不能看到个人互动状态。

## 测试计划

Java：

- `InteractionServiceTest`：点赞、取消点赞、收藏、取消收藏、重复操作。
- `NotificationServiceTest`：列表、标记已读、只能操作自己的通知。
- `ForumServiceTest`：`sort=hot`、`sort=unanswered`。

Vue：

- `npm.cmd run typecheck`
- `npm.cmd run build`
- 手工检查移动端和桌面端通知页面。

联调：

- `scripts/verify-local-flow.ps1` 扩展：
  - 查询 interaction status。
  - 取消点赞和取消收藏。
  - 标记通知已读。
  - 查询收藏列表。

## M3 验收标准

- 登录用户能看到主题是否已点赞、已收藏。
- 点赞、取消点赞、收藏、取消收藏都能真实落库并刷新页面状态。
- 通知中心能列出当前用户通知并标记已读。
- 顶部通知入口能体现未读状态。
- 用户能打开个人收藏列表。
- 首页 `hot` 排序和后端排序一致。
- 后端和前端检查通过。
- M3 开发手册写清楚完成范围、验证结果和遗留风险。

## 暂不放入 M3

- WebSocket 实时通知。
- Redis 未读数缓存。
- 邮件或短信通知。
- 复杂楼中楼通知。
- 推荐系统。
- AI 个性化通知摘要。
