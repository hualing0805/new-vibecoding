# M2.5 真实联调与核心流程测试开发手册

## 阶段目标

M2.5 的目标是把 M2 已完成的 MySQL-backed 后端和真实 JWT 登录态，收口成可本地稳定联调、可按步骤验收、出错时可读的论坛核心流程。

本阶段不继续堆新功能，重点是让已有能力更可靠：启动有脚本、验收有脚本、页面错误可见、核心服务有测试、下一阶段有明确规划。

## 需要完成的事情

- 屏蔽根目录本地临时 `ssh` 文件，避免污染每轮 `git status`。
- 增加本地联调启动脚本，统一启动 MySQL、Java、Python Agent 和 Vue 前端。
- 增加本地联调停止脚本，停止由启动脚本管理的后台进程。
- 增加核心 HTTP 流程验收脚本。
- 前端真实 API 模式下，写操作失败不能静默 fallback，需要显示明确错误。
- 补充 Java 服务层核心流程测试。
- 更新 README 和开发脚本入口。
- 规划 M3 开发思路。

## 已经如何完成

### 本地脚本

- 新增 `scripts/start-local-stack.ps1`：
  - 使用 Docker Compose 启动 MySQL。
  - 优先使用系统 Maven 或仓库自带 Maven 启动 Java 后端。
  - 使用本地 Python 或 Agent 虚拟环境启动 Python Agent。
  - 使用 `npm.cmd run dev` 启动 Vue 前端。
  - 后台进程 PID 和日志写入 `logs/local-stack/`。
- 新增 `scripts/stop-local-stack.ps1`：
  - 读取 `logs/local-stack/pids/*.pid`。
  - 停止脚本启动的 Java、Agent、前端进程。
- 新增 `scripts/verify-local-flow.ps1`：
  - 验证 `/api/health`。
  - 登录 seed 管理员账号。
  - 注册验收用户。
  - 获取当前用户、板块列表。
  - 创建主题、读取详情、创建回复。
  - 点赞、收藏。
  - 查询通知。
  - 创建举报并用管理员账号处理举报。
- 更新 `scripts/dev.ps1`，把 M2.5 联调脚本作为优先入口展示。

## 本地使用或验收步骤

1. 启动本地服务。

```powershell
.\scripts\start-local-stack.ps1
```

2. 等待 Java 后端健康后执行核心流程验收。

```powershell
.\scripts\verify-local-flow.ps1
```

3. 打开前端。

```text
http://localhost:5173
```

4. 使用 seed 账号登录。

```text
username: demo
password: ThreadMind@123
```

5. 人工验收页面错误状态。

- 未登录时进入发帖页应跳转登录页。
- 登录后发布主题，失败时页面应显示错误。
- 帖子详情页点赞、收藏、回复失败时页面应显示错误。
- 管理页无权限时应回到首页；后端拒绝时页面显示权限错误。

6. 停止本地脚本启动的服务。

```powershell
.\scripts\stop-local-stack.ps1
```

## 遗留风险

- `verify-local-flow.ps1` 依赖本地 MySQL、Java 服务和 seed 管理员账号，属于联调验收脚本，不替代数据库集成测试。
- 前端仍保留公开读取的 mock fallback，后续 M3 可以增加 API 状态提示和重试入口。
- `start-local-stack.ps1` 不自动安装 Python 或 Node 依赖，依赖缺失时会跳过对应服务并提示。
- 后端还没有使用 Testcontainers 或真实测试库覆盖 repository SQL。
