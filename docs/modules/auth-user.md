# 账号与用户模块

## 职责

账号与用户模块负责识别“是谁在使用论坛”，并把用户身份交给其他模块做权限和归属判断。

第一阶段功能：

- 注册。
- 登录。
- 获取当前用户。
- 返回角色列表。

## 设计思路

注册和登录都只返回必要用户摘要，不把密码、邮箱验证状态、登录失败次数等内部字段交给前端。前端只需要知道当前用户是谁、有哪些角色、是否能进入管理页。

M1 阶段返回 demo token，是为了让前端和其他模块先能串流程。正式实现时 token 应替换为 JWT，用户信息从数据库读取，密码使用 BCrypt 哈希。

## 功能设计

### 注册

输入用户名、邮箱、密码、昵称。后端负责校验字段长度和邮箱格式。

设计理念：注册接口不承担“创建社区身份以外”的工作，不自动发帖、不自动关注板块。这样注册失败、邮箱验证和资料补全都可以独立演进。

### 登录

输入用户名和密码，返回 token 和用户摘要。

设计理念：登录只解决身份建立。权限判断不能只靠前端是否显示按钮，后端每个写接口仍要做资源归属和角色检查。

### 当前用户

返回当前用户摘要：ID、用户名、昵称、头像、角色。

设计理念：前端很多页面都需要当前用户信息，但不应该反复解析 token。统一接口能让登录态刷新、权限菜单和用户资料显示走同一条路径。

## 后续实现要点

- `users.username` 和 `users.email` 必须唯一。
- 密码只保存 BCrypt 哈希。
- 登录失败要做频率限制。
- JWT 密钥从环境变量读取，不提交仓库。
- 用户状态为 `LOCKED` 或 `DISABLED` 时，登录应返回明确错误。
