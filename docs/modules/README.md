# 模块设计索引

ThreadMind 的模块设计按“论坛主流程优先，AI 能力受控接入”来组织。每个模块文档都回答三个问题：这个模块负责什么，为什么这样划边界，后续从演示实现替换为数据库实现时要保留哪些约定。

## 模块地图

| 模块 | 文档 | 第一阶段职责 |
| --- | --- | --- |
| 账号与用户 | `auth-user.md` | 登录、注册、当前用户、角色基线 |
| 论坛内容 | `forum-content.md` | 板块、帖子、回复、标签 |
| 互动与通知 | `interaction-notification.md` | 点赞、收藏、通知 |
| 治理 | `moderation.md` | 举报、处理、审计记录 |
| AI Agent | `agent.md` | AI 网关、内部工具、场景响应 |
| 前端体验 | `frontend.md` | 页面信息架构、状态、API 兜底 |

## 总体设计理念

论坛功能永远是主干。用户浏览、发帖、回复、点赞和管理内容时，不应该因为 AI 服务不可用而中断。

Java 后端是业务事实的唯一入口。它负责权限、状态变化、审计和数据库写入。Python Agent 只负责生成建议、摘要、问答和风险提示，不直接决定业务状态。

前端页面先服务真实操作，不做展示型首页。首页就是帖子流，发帖页就是编辑器，管理页就是治理队列。AI 入口放在任务旁边，让它成为辅助工具，而不是页面主题。

## 当前实现边界

当前 Java 侧使用内存应用服务保存演示状态，接口和 DTO 已按后续数据库实现设计。这样做有两个原因：

- 先稳定 API 和模块边界，避免前后端并行时反复改契约。
- 当前环境缺 Maven，无法可靠验证完整 JDBC/MyBatis 编译链，先不写大面积数据库访问代码。

替换为 MySQL Repository 时，Controller 和前端 API 可以保持不变，只替换 Service 内的数据来源。
