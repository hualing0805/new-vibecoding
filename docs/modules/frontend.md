# 前端体验模块

## 职责

前端负责把论坛主流程组织成清晰可用的页面。它不承担业务判断，也不直接调用 Python Agent 或 MySQL。

第一阶段页面：

- 首页。
- 帖子详情。
- 发帖编辑器。
- 站内助手。
- 治理后台。
- 登录页。
- 顶部全局搜索入口。
- AI 审计台和用户 AI 历史入口。

## 设计思路

首页直接展示帖子流和板块状态。用户进入系统后最常做的事是看内容、找内容、发内容，不需要先经过宣传页。

AI 入口以 Dock、按钮和侧栏出现。它应该靠近写作、阅读和治理任务，而不是占据整个产品叙事。

API 调用采用“后端优先，mock 兜底”。如果 Java 后端未启动，页面仍能展示演示数据；后端可用时，页面自动使用真实接口。M5-M10 新增的 AI 审计、摘要缓存、搜索和管理指标同样保留 mock fallback，避免本地设计页面时被后端启动状态阻断。

## 功能设计

### 首页

显示状态指标、排序控件、帖子列表、AI Dock 和板块列表。M6 起首页也读取顶部搜索写入的 `keyword` 查询参数，并复用帖子列表 API 进行过滤。

设计理念：论坛首页要高信息密度，但不能拥挤。核心信息是标题、板块、摘要、作者、标签和互动数。

### 帖子详情

显示正文、AI 摘要、互动动作、回复列表和回复框。

设计理念：详情页要把阅读、判断和参与放在同一个地方。AI 摘要放右侧或下沉，不遮挡原文。

M5 起摘要区提供刷新按钮。默认摘要可来自缓存，刷新失败时保留当前摘要，并在错误区提示用户。

### 发帖编辑器

显示标题、板块、正文、标签、预览和 AI 写作辅助。

设计理念：写作时最怕工具打断思路，所以 AI 操作放侧栏，用户手动采纳，不自动覆盖草稿。

### 站内助手

显示问答消息、引用范围、工具调用和历史会话。

设计理念：用户需要知道助手能看什么、不能看什么。引用范围能建立边界感。

M6 起助手页展示当前用户自己的 AI session 历史，点击历史可恢复消息与工具调用，并沿用 `sessionId` 继续提问。

### 治理后台

显示举报队列、处理动作、AI 审计、指标和详情状态。

设计理念：管理台是重复工作界面，要用表格和批量动作，不用装饰性卡片。

M7-M8 起管理台分为治理和 AI 审计两个标签。治理标签支持状态筛选和详情侧栏；AI 审计标签展示指标、session 列表、消息和工具调用摘要。

## 后续实现要点

- API Client 统一处理 `ApiResponse`。
- 每个页面要有加载、错误和空状态。
- 所有核心控件要有键盘 focus 样式。
- 移动端保留浏览、发帖、回复，复杂治理功能可优先服务桌面端。
