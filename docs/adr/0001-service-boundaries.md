# ADR 0001：服务边界

日期：2026-08-04  
状态：已接受

## 背景

项目同时包含 Java 后端、Vue3 前端、Python Agent 和 MySQL。AI 能力会读取论坛内容并生成建议，如果让 Python 直接访问数据库，短期开发会更快，但权限、审计、数据脱敏和业务一致性会变得难控。

## 决策

Java Spring Boot 是主业务服务，负责认证、权限、事务、数据库写入、审计和对外 API。

Vue3 前端只调用 Java 的 `/api/**`。

Python FastAPI Agent 只作为 AI 能力服务存在。它可以接收 Java 提供的上下文，也可以通过 Java 暴露的内部工具接口查询授权数据，但不直接连接 MySQL，不直接写业务表。

MySQL 只被 Java 主业务服务直接访问。后续即使加入 Redis、搜索引擎或向量库，也不能绕开 Java 的权限边界修改主业务数据。

## 影响

收益：

- 权限判断集中，出错面更小。
- AI 调用链路可审计。
- Agent 服务故障时，论坛核心功能仍可用。
- 后续替换模型或 Agent 编排方式，不会牵动主业务表写入规则。

代价：

- Agent 获取数据要多走一次 Java 工具接口。
- Java 需要维护一组面向 Agent 的内部查询接口。
- 本地开发要启动两个后端服务。

## 后续

MVP 先用 Java Agent Gateway 直接转发到 Python。进入 M4 后，再把站内搜索、内容摘要缓存、工具调用审计补完整。
